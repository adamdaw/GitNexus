### Reproducible spike harness (workspace is ephemeral /tmp)

`sample.cls` (representative Apex):
```apex
public with sharing class AccountService extends BaseService implements Schedulable {
    private final Integer maxRetries = 3;
    public String name { get; set; }
    public AccountService(String name) { super(); this.name = name; }
    @AuraEnabled
    public static List<Account> getAccounts(Id ownerId) {
        AccountService svc = new AccountService('svc');
        return svc.query(ownerId);
    }
    public List<Account> query(Id ownerId) {
        return [SELECT Id, Name FROM Account WHERE OwnerId = :ownerId];
    }
    public void execute(SchedulableContext ctx) { System.debug(this.name); }
    public enum Status { ACTIVE, INACTIVE }
}
```

`test.cjs` (load + parse harness against tree-sitter@0.21.1):
```js
const Parser = require('tree-sitter');
const Apex = require('./bindings/node/index.js'); // {name, language, nodeTypeInfo}
const fs = require('fs');
const p = new Parser();
p.setLanguage(Apex);                              // pass the wrapper, NOT Apex.language
const tree = p.parse(fs.readFileSync('./sample.cls','utf8'));
const root = tree.rootNode;
const count = n => (n.type==='ERROR'||n.isMissing?1:0) + Array.from({length:n.childCount},(_,i)=>count(n.child(i))).reduce((a,b)=>a+b,0);
console.log(root.type, root.hasError, count(root)); // parser_output false 0
```

Build recipe (apex-only, Swift-shaped): copy regenerated `apex/src/` → `src/`; `binding.gyp` sources
`["src/parser.c","bindings/node/binding.cc"]`; `binding.cc` exposes only `tree_sitter_apex` with the
BLAKE2 `LANGUAGE_TYPE_TAG`; `index.js` = `node-gyp-build(root)` + attach `nodeTypeInfo` from
`src/node-types.json`. Deps: `tree-sitter@0.21.1`, `node-addon-api@^8`, `node-gyp-build@^4`. `npm install`
then `node test.cjs`.

**Gotcha (cost me one run):** pass the *wrapper object* `{name,language,nodeTypeInfo}` to `setLanguage`,
not the raw `External` — tree-sitter@0.21.1 builds `nodeSubclasses` from `language.nodeTypeInfo` on the
passed object (index.js:341/834). Passing the bare External crashes at node access (`nodeSubclasses` undefined).

## Plugin dogfood finding #5 — decomposition checkpoint is an unenforced Gate-1 sub-pass

Discovered entering Phase 2: the **Gate 1 decomposition checkpoint never ran.** `pass-records/gate1.md`
covers epic-SRS fidelity only; SRS §11 explicitly defers the formal work-item cut + its checkpoint to
"once this epic SRS clears Gate 1," and `vsdd-advance` moved us to Phase 2 on the epic-fidelity half
alone. `state.json` tracks only `gates_passed:[1]` — nothing modelled the sub-pass, so nothing blocked
advancement without the work-item decomposition existing.

**Hard-gate design (fold back into `~/Projects/Home/vsdd`, branch `feature/plugin`):**
1. Record the unit type in `state.json` (e.g. `"unit_type": "epic" | "work-item"`), set during
   `vsdd-init` or Phase 1. (Init default could be `epic`; a single work item flips it.)
2. In `vsdd-advance.js`, when clearing **Gate 1 for an epic**, the artifact-presence precondition
   (the same `satisfied()` mechanism already used) MUST additionally require BOTH:
   - the decomposition artifact (`.vsdd/work-items.md` or `.vsdd/work-items/`), non-empty; and
   - a decomposition-checkpoint pass record (`.vsdd/pass-records/gate1-decomposition.md`), non-empty.
   Refuse the advance, naming whichever is absent — exactly like the existing Gate-1 artifact check.
   Content fidelity stays the human/adversary gate; presence of the cut + its pass record is the
   machine-enforceable floor. For a `work-item` unit, neither is required (no decomposition).
This makes the methodology's "Gate 1 decomposition checkpoint is a Gate-1 sub-pass" claim real in the
machine, closing the gap that let this run skip it.
