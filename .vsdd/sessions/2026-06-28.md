## Dogfood finding #7 — Gate-2 verification split (spec vs host-code grounding)

Gate 2 (spec fidelity) reviews the SDD against SRS + Constitution under **evidence isolation** — the
adversary cannot see the host codebase. So any SDD clause that asserts **host-API / host-extractor
behaviour as established fact** is, from the gate's view, an unverified claim — and a Builder
(me) repeatedly authored such claims, drawing a fresh major nearly every clean round (enum-constant
name path, multi-declarator emission, `extractName`, `NodeProperties` index signature, etc.).

**Fix (now applied to this SDD; fold back to methodology §A.11 SDD-authoring + the plugin):** an SDD
must split its claims: (1) **grammar / §A.6 facts** are RESEARCH-verified and are Gate-2 evidence;
(2) **host-API/extractor behaviours WI-1 relies on** are stated as **WI-1 design obligations verified
at Gate 3** (tests against the real host), never as Gate-2-settled facts. A single governing
"verification split" note covers the whole SDD. This is implicit in VSDD's gate structure (Gate 2 =
spec; Gate 3 = tests vs spec) but should be made explicit in §A.11 so Builders don't smuggle
host-code assertions into the Gate-2 contract.

**Contamination audit (Adam's catch, 2026-06-28):** introducing the verification-split mid-Gate-2
obligated re-examining earlier fixes made without it (same discipline as the context-free re-audit).
Result: RESEARCH-001 clean (all grammar facts); SDD fixes substantively fine but several were *framed*
as Gate-2-settled host facts — now globally governed by the verification-split note, with three
residual "observed host-code" markers reframed to "Gate-3-confirmed". No fix had to be reverted.
